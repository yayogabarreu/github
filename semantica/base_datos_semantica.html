Concepto y tipos de bases de datos.

Bases de datos relacionales (RDBMS)

Las Bases de datos Relacionales (RDBMS) son sistemas de organización de información basados en el modelo relacional, donde los datos se estructuran de forma lógica y predecible.

En este tipo de sistemas, la información se almacena en tablas independientes (también llamadas relaciones), las cuales representan entidades del mundo real, como "Clientes" o "Pedidos".

La gran ventaja de las RDBMS es su capacidad para conectar e interactuar con distintas tablas mediante relaciones matemáticas y lógicas, garantizando la integridad y consistencia de los datos. Entre los ejemplos más comunes y utilizados en la industria tecnológica se encuentran MySQL, PostgreSQL, Oracle Database y Microsoft SQL Server.

Bases de datos no relacionales (NoSQL)

Las bases de datos No Relacionales (NoSQL) son sistemas de gestión de almacenamiento de información diseñados para manejar grandes volúmenes de datos que no se adaptan al modelo tradicional de tablas y columnas de las bases de datos relacionales (SQL).

Su principal ventaja es la flexibilidad, ya que permiten trabajar con almacenamiento no estructurado o semiestructurado, eliminando la necesidad de un esquema rígido y fijo.


Estructura de una base de datos relacional.

Componentes fundamentales

Para definir la estructura dentro de un modelo relacional se emeplean los siguientes elementos:

  • Tablas (Entidades): Estructuras donde se organizan los datos.
  • Campos (Atributos): Columnas que definen la tipología de información.
  • Registros (Tuplas) Filas que contienen cada instancia concreta de datos.
  • Claves primarias (Primary Keys): Identificadores únicos de cada registro.

Relaciones entre tablas

Cardinalidades y llaves foraneas

  • Una relación 1:1 (uno a uno) en SQL ocurre cuando un registro de una tabla A se relaciona con un único registro de una tabla B, y viceversa.
  • Una relación 1:N (uno a muchos) en bases de datos ocurre cuando un registro de una tabla principal (el "uno") puede estar vinculado con múltiples registros en una tabla secundaria (el "muchos"), pero cada registro de la tabla secundaria pertenece a uno solo de la tabla principal.
  • Una relación N:M (muchos a muchos) en bases de datos ocurre cuando un registro de una tabla (Tabla A) 7 puede estar asociado con varios registros de otra tabla (Tabla B), y viceversa.
  • Una clave foránea (foreign key) en SQL es una columna (o conjunto de columnas) en una tabla que apunta a la clave primaria (primary key) o restricción única (unique) de otra tabla para conectar ambas mediante una relación lógica.
